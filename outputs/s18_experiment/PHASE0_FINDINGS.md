但有一個必須寫進方法章節的細節:**7 次過零 ≠ 4 次指令換向**。從圖可見每次階梯後
`rotor_speed` 會先衝正再擺負(定位整定的過衝振鈴)才收斂到 0,因此零交越同時來自兩種機制:

1. **指令換向**(demand 往上 vs 往下)—— 真正的背隙激勵

`dead_zone_width` / `reversal_error` 用 `v[i]*v[i-1] < 0` 判定,會把兩者混在一起。
Phase 1 需決定是否用 `transitions` 欄位(每 run 5 個連號值,見 JSON)只鎖定指令換向點。

## 4. `dsp_analytics` 相容性:2 個特徵退化成常數 ⚠️

把 8 個函數對 3 個 LN run 實跑,run 間標準差:

| 特徵 | run1 | run2 | run3 | run 間 std | 狀態 |
|---|---|---|---|---|---|
| `BL_DeadZone` | 0.05 | 0.05 | 0.05 | **0** | ⚠️ **常數** |
| `BL_ReversalErr` | 3.894 | 4.537 | 6.037 | 1.100 | ✅ |
| `BL_HystArea` | 0.00434 | 0.00758 | 0.01822 | 0.00726 | ✅ |
| `BL_DirFE_Asym` | 2.193 | 3.023 | 4.269 | 1.045 | ✅ |
| `STIFF_Slope` | 0.295 | 0.609 | 0.987 | 0.347 | ✅ |
| `STIFF_ComplStd` | 0.01442 | 0.01536 | 0.00718 | 0.00447 | ✅ |
| `FR_Coulomb` | 2.346 | 2.364 | 2.433 | 0.0458 | ✅ |
| `FR_Viscous` | 0.001 | 0.001 | 0.001 | **0** | ⚠️ **常數** |

兩個退化的根因都是**寫死的常數與本資料尺度不匹配**:

**`BL_DeadZone` → 恆回傳預設值 0.05。** 函數在反轉後往後搜尋 **20 samples**,要求實際位置
移動 > **0.05** 才記一次死區。50 kHz 下 20 samples 只有 **0.4 ms**;實測位移速率約 55 units/s,
0.4 ms 內只移動 ≈ 0.022 < 0.05,**永遠搜不到**,於是 `dead_zones` 恆空、回傳 `return 0.05` 的預設值。

**`FR_Viscous` → 恆回傳預設值 0.001。** `stribeck_friction_parameters` 的黏滯項只用
`|v| > 500` 的樣本擬合,但本資料 **|v| 最大僅 183.02,命中 0 筆**(庫倫項的 `|v| < 100`
命中 763,885 / 899,853 筆,所以 `FR_Coulomb` 正常)。

**這不是資料的問題,是函數常數的問題。** 兩者都需要按 50 kHz 與 ±183 的速度尺度換算窗長/門檻,
否則這 2 個特徵在 Phase 1 會以常數進入特徵表——單調性檢定必然不顯著,而且是假陰性。

## 5. 另一項與設計書的落差:`STIFF_Slope` 算的不是 torque 斜率

設計書 §2 第 5 項寫「`force_displacement_slope(actual, FE, ...)`:**torque** 對位移誤差的斜率」,
但 `dsp_analytics` 的實作是 `np.polyfit(fe, pos, 1)[0]` —— **位置對 FE** 的斜率,
第三個參數 `stiffness` 只在 `var(fe) < 1e-8` 時當退路回傳。兩者物理意義不同。
本次計算已照實作原樣呼叫(未改寫函數),數值有變異,但**「等效剛性」的解讀需要重新確認**。
