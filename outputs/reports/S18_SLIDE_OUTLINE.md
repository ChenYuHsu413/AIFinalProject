# A. 一頁摘要

## 情境 18（滾珠絲槓背隙/磨損）於真實 FMCRD 資料之驗證

**問題**：40 情境框架宣稱可診斷滾珠絲槓退化，其特徵家族（背隙 BL / 剛性 STIFF / 摩擦 FR）
是否真能在真實資料上隨退化單調惡化？此前僅有設計假設，未經實證。

**方法**：對 FMCRD（106 GB、8 檔、1,465 個 6 秒定位循環）串流計算 per-run 物理特徵。
全程預註冊：門檻、主從判準、消融變體、test 預期皆在碰 test 之前寫入 config 並鎖定。
**train 665 段建基線與診斷，test 800 段只評估一次。**

**結果——部分驗證，且失敗的一半比成功的一半更有價值：**

- **摩擦與剛性成立**。`FR_Coulomb`（ρ=0.794）與 `STIFF_TorqueSlope`（ρ=−0.496）
  在**排除負載混淆**的 within-noisy 軌上與退化等級單調相關（p<0.001），
  重度退化偵測 AUC 0.98–0.99、觸發率 90%。對照組 `FE_RMS`/`FE_Max` 全程無訊號（|ρ|≤0.02），
  證明其判別力**非追隨誤差之換皮**。
- **背隙族不成立——但歸因明確**。四項 BL 特徵均無訊號，原因**不是訊號微弱，而是激勵條件不支持**：
  本工況為階梯定位循環，既無連續反轉軌跡（遲滯迴圈不存在），指令換向亦僅 0–3 次、12% 的 run 為 0。
  此結論由**四個機制獨立的證據三角化**（窗長敏感度、迴圈不存在、事件數、分軌檢定）。
- **早期邊界未突破**。LN/LO 的 AUC ≤ 0.556，經四次獨立確認（AUC、觸發率、severity 分級、消融混淆矩陣），
  與主專案 E1–E5 之類別不平衡結論互相印證。
- **消融：無增量判別力**。加入 s18 特徵後 macro-F1 未提升（0.8187 → 0.8124 / 0.7581），
  其資訊已被既有 21 維涵蓋；**價值在物理可解釋性與根因排名，不在新增判別力**。

**貢獻**：(1) 將「背隙特徵需反轉/連續激勵方可觀測」由設計假設**升級為實證命題**，
回饋 40 情境框架——**激勵條件應納入情境可行性分級維度**；
(2) 暴露並修正 `dsp_analytics` 四項規格與實作落差，以逐位元等價測試補上其原本不存在的測試；
(3) 診斷輸出新增 `not_estimable` 第三態，使系統首次能誠實表達「此故障路徑本工況看不見」。

**誠實揭露**：FMCRD 為高擬真物理**模擬**資料集，非工廠遙測。健康基線取自零負載檔案，
故 LN 錨定指標含退化與負載之混合效應，退化推論一律以 within-noisy 軌為準。

# B. 投影片大綱（8 頁 + 備用）

## 頁 1 — 問題與定位

- 標題：**情境 18：機械傳動層——真實資料部分驗證**
- 一句話：40 情境框架說得出口，但**背隙特徵真的量得到嗎？**
- 三情境現況條列：01 已驗證（控制層）｜**18 本次**（機械傳動層）｜34 方法就緒（電磁層）
- 底線標註：FMCRD = 高擬真**模擬**，非工廠遙測

## 頁 2 — 實驗紀律（先講方法，再講結果）

**這頁是整份簡報的信用基礎，不要跳過。**

- 兩遍掃描：特徵管線只讀訊號欄，標註表只讀 DV/ylabel → 防洩漏是**架構保證**非自律
- 預註冊：門檻、主從判準、消融變體、test 預期，全部在碰 test 前鎖進 config
- **test 800 段只評估一次**
- 逐位元等價測試：參數化重實作必須與原函數 bit-identical
- 一句話收尾：**「所有讓結果變好看的路，都在看到結果之前就封死了。」**

## 頁 3 — Phase 0 的意外收穫：規格與實作落差

- `dsp_analytics` 四項函數**從未被真實資料檢驗過**：
  | 函數 | 落差 |
  |---|---|
  | `dead_zone_width` | 窗參數寫死 20 samples（隱含 1 kHz），50 kHz 下恆回傳預設常數 `0.05` |
  | `force_displacement_slope` | **名實不符**——完全未用到 torque |
  | `stribeck_friction_parameters` | 高速門檻 `\|v\|>500`，本資料 \|v\|≤183，**命中 0 筆** |
  | `del_pos` | 語意誤判——實為相對 run 起點的**指令**位移 |
- 訊息：**規格與實作的落差，只有真實資料能暴露。**

## 頁 4 — 成立的部分（**主圖：Stribeck 平面**）

- 圖：`fig1_stribeck_test.png`（LN vs HI，低速帶 |v|<100 標色，虛線為 mean|torque|）
- 肉眼可見 HI 的扭矩包絡整體抬升 = `FR_Coulomb` 所量
- 數字：within-noisy ρ=0.794、LO vs HI AUC **0.983**；`STIFF_TorqueSlope` ρ=−0.496
- 對照組 `FE_RMS` 全程無訊號 → **不是換皮**
- 副圖（可選）：`fig1b_fe_torque_slope_test.png`

## 頁 5 — 不成立的部分,以及為什麼這才是重點

**建議這頁講最久。**

- 背隙族四項全部無訊號
- **四重證據三角化**（四個機制完全獨立）：
  1. 窗長 10/20/40 ms 給出**同一結果** → 非調參問題
  2. demand–actual 為階梯路徑，**遲滯迴圈不存在**（附錄圖）
  3. 指令換向僅 0–3 次，**12% 的 run 為 0**
  4. within-noisy 分軌檢定無訊號
- **對照組（殺手級對比）**：同一特徵、同一份資料，兩種處理——
  | | 原專案做法 | 本實驗做法 |
  |---|---|---|
  | 量不到時 | `return 0.05` 預設常數，**假裝有值** | 輸出 NaN，四種方式證明測不到並定位原因 |
  | 答辯結果 | 一個問題擊穿 | 站得住 |
- 訊息：**有價值的 N/A 不是「我們沒測到」，是「我們證明了測不到，並找出原因」。**

## 頁 6 — 混淆控制的教訓（方法論亮點）

- `BL_ReversalErr_zc` 全類別檢定 **p=0.0005**，看似 BL 族終於有訊號
- 偏相關控制事件數後**仍為 0.237（p<0.001）——並未拆穿它**
- within-noisy **分軌**檢定：ρ=0.075（p=0.067）→ 訊號全來自零負載 LN vs 加載三類
- 訊息：**混淆控制要控制資料結構裡真實存在的變因（負載條件），而非事前猜到的變因（事件數）。**
  若無此軌，這會是整份實驗唯一的錯誤結論。

## 頁 7 — 消融與診斷輸出

- 消融（LR 釘死、閘門驗證）：0.8187 → B 0.8124（−0.006）／A 0.7581（−0.061）
- 結論：**資訊已被既有 21 維涵蓋；價值在物理可解釋性與根因排名**
- 圖：`fig4_zscore_ranking_test.png`（HI run 708，`STIFF_TorqueSlope` z=−11.6 主導）
- 診斷 JSON：新增 **`not_estimable` 第三態**——區分「量不到」與「量到但正常」；
  背隙補償不產出，標註「本工況無反轉激勵，背隙量不可估計」
- 可帶一句：合約 v1.1 提案七條，含 hash chain 驗證失效之修正

## 頁 8 — 結論與回饋

- **情境 18：部分驗證**（摩擦/剛性 ✅；背隙：激勵條件不支持 ⚠️；LN/LO 邊界未突破）
- 對 40 情境框架的回饋：**激勵條件應成為情境可行性分級的維度之一**
- 兩份工作的會師：框架保留（三情境、特徵模板、診斷合約沿用），
  宣稱改掉（每個字都有實證背書），`dsp_analytics` 真的在 repo 管線裡跑出結果
- 誠實揭露 + 未竟事項（FMCRD 授權待確認）

## 講者提醒

1. **不要說「情境 18 驗證成功」**。18 的原始複合目標是背隙+剛性+摩擦三支柱，
   實證是兩立一不可觀測，措辭必須反映這個結構。
2. 所有 LN 錨定的數字（AUC、觸發率 12.5%/90.0%）旁邊都要帶一句
   **「基線為零負載，含負載混合效應」**。
3. `FR_Viscous` 若被問到：已依預註冊判準標 N/A，**不因 test 出現 ρ=−0.407 而翻案**——
   這是紀律不是遺漏。
4. critical 級在健康件上仍有 **2.5%** 誤報，如實講，別只講 HI 的 90%。
